# Skill: Documentation Review

Review docs for:
- Clarity
- Missing assumptions
- Contradictions
- Outdated info — **check reader-followable literals against the code**, not against comments or older docs (paths, filenames, commands, flags, env vars, API fields, UI control labels); see `documentation-rules.md` § Verifying documented literals against code
- AI-agent usability
- Migration friendliness

**When you report more than one issue**, render them as a table per `workflow-rules.md` § Work listing format — only the columns the project can fill, never invented.
