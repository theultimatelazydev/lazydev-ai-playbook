# Skill: Feature Planning

Use this skill to break a feature into implementation-ready scope.

Include:
- Summary
- User value
- MVP scope
- Future scope
- Non-goals
- Acceptance criteria
- Risks
- Open questions

**Non-goals follow the scope rule.** Only record a non-goal you can point at — a named different feature, a decided constraint with its reference, or a cut the maintainer stated. Anything you merely *think* should be deferred is a question to raise, not a non-goal to write down (see `workflow-rules.md` § Scope belongs to the maintainer). Each MVP scope item needs a **Definition of done** — the user-visible outcome that stops a slice from wearing the whole feature's name.

**When you present the plan as a list of items** (waves, scope items, or resulting issues), render it as a table per `workflow-rules.md` § Work listing format — one row per item, only the columns the project can fill.
